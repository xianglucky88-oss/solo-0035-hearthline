# 炉迹 · 连续炉料盘热历核对台

炉迹把连续炉的料盘过门记录和固定测点读数对齐到同一炉次秒轴。工艺数据员可以查看每盘的实际路线、炉位撞占、采样或校准缺口，以及每个阶段最长的连续达标秒数。复核员逐盘记录签认结果，将要交接的料盘冻结为带来源摘要的清单。

## 本机运行

需要 Python 3.9 或更新版本和支持 ES Modules 的现代浏览器。应用使用 Python 标准库和 SQLite，浏览器端使用原生 HTML、CSS、JavaScript，无需安装应用依赖。运行源码检查另需 Node.js。

```sh
python3 -B -m hearthline
```

在浏览器打开 `http://127.0.0.1:8735`。默认数据库为 `var/hearthline.sqlite`，可用 `--db /path/to/hearth.sqlite` 指定新库，用 `--port` 更换端口。服务仅监听本机回环。合成示例用于演示数据规则。

## 走一遍示例

1. 在空工作台选「打开示例资料」，然后「预检」或「保存到炉次档案」。默认示例文件为 `examples/alder.json`，也可直接上传 JSON 文件。
2. 炉次 `ALDER-18` 有 6 个料盘。`A17` 的保温阶段中途切换校准，35 秒有证，最长连续达标 17 秒。`A24` 的保温阶段有缺口，`A31` 和 `A42` 在 `P2` 撞占，`A55` 保温时长不足，`A68` 缺一张离位票。
3. 展开「查看原始证据」核对每段用到的过门票、样点和校准票。对证据齐备的料盘填写复核人与依据，选择「签认通过」；其余盘可暂缓并继续复核。
4. 打开「交接清单」，从已通过的盘中为一个批号选盘并「生成预核」。确认时系统在同一事务复核各盘均未交接、且生效通过签认仍是预核那条，再整批冻结。已交接盘停止追加签认，其他盘可继续签认并另批交接；并发争同一盘只许一批成功。
5. 在已冻结批次中按批号下载 JSON 或 CSV（只含本批盘），再点「复算存档」核对输入、分析和各冻结件。整炉冻结的炉次继续整炉冻结，当时未入件的盘也不能补签或分批交接，原件照常下载与复算。
